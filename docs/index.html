The Burl programming language.
Small enough to know by heart.

Burl is a small scripting language designed to be written easily — by people, and by the machines that help them. Functions are values, imports are function calls, maps and lists behave the way you expect, and every error names its line and its crime.

Simple like Linux. Forward-minded like its name implies. One clear spec, a zero-dependency interpreter, and a compatibility covenant that promises tomorrow’s Burl will still run today’s code.

// The whole language fits in one head.
fn fib(n) {
    if n < 2 { return n }
    return fib(n - 1) + fib(n - 2)
}

let sagas = [
    { "name": "Eiríks saga rauða", "year": 1260 },
    { "name": "Grœnlandinga saga", "year": 1190 },
]

for s in sagas {
    print("{s.name} — settled {s.year}")
}

A language with a point of view

Every choice in Burl serves one goal: code that a person and a language model can both write, read, and trust.

◆Functions are values

Closures, higher-order functions, passes-to-and-returns-from — without classes, inheritance, or ceremony. fn is a value like any other.

◆Modules are function calls

No import statements, no module syntax. let saga = import("lib/saga.burl") loads a file and hands you a map of its functions. That’s the whole system.

◆Hints that earn their keep

Optional type hints are checked by burl check — advisory, never load-bearing. Silent when it can’t prove a claim; loud when it can.

◆Honest errors

Every error message contains line N and names the offending operation. Parse errors stop before the first statement runs — no half-executed programs.

◆One number type

No int/float split in the surface syntax — the spec names one number type and the language stands by it. Precision promises are written down in SPEC.md 5.1, and where reality disagrees, the ledger says so.

◆Built for two readers

Plain values everywhere, predictable grammar, no punctuation traps, no magic. Small enough for a spec that AI can hold entirely in context.

¶

The compatibility covenant

From 1.0 onward, nothing may be removed or redefined in a way that breaks a correct program, without a two-major-version deprecation — and every promise is written down in the spec, the changelog, and a public deficiency ledger before 1.0 ships. Burl takes compatibility seriously before it takes features seriously.
