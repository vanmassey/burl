Burl

Simple like Linux, forward-minded like its author, and equally pleasant for humans and AI to write.

GitHub Spec Roadmap Changelog

What Burl is

A small scripting language that fits in one file of specification and one dependency-free package. One number type, dynamic values with optional runtime-checked hints, brace syntax, loud errors with line numbers. Nothing clever. Clever is what breaks in year three.

fn greet(name) {
    return "Hello, {name}!"
}

for name in ["Ada", "Grace", "Linus"] {
    print(greet(name))
}

// hints are optional; the checker reads them, nothing else changes
fn double(n : number) : number {
    return n * 2
}

Quick start

pip install .          # from a clone; no dependencies beyond Python 3.8+
burl examples/fib.burl      # run a program
burl check examples/fib.burl # check it first: unknown names, arity, hints
burl                        # REPL

Principles

  • Compatible. From 1.0 onward, a correct program never breaks and never changes meaning. The covenant in the spec is binding.
  • Simple. One spec file, one stdlib of 30-odd honest builtins, no magic.
  • Loud. Every error names its line and its operation. Misuse should fail at first use, not drift.
  • For humans and machines. Grammar you can hold in your head, hints a checker can read, interpolation "n = {x}" instead of format archaeology.

Where it is going

Burst the features, then freeze and shake. The current voyage: a static checker (0.3, done), the interpreter rewritten in Burl itself (0.4), a bytecode VM (0.5), standalone executables (0.6), a real standard library (0.7), then a deliberately long release-candidate before 1.0 — “Landfall”. The roadmap is public and each version has a definition of done that CI can check.

A burl is the rounded knot in wood — small, dense, and prized for holding its shape. Code and docs: github.com/vanmassey/burl. MIT.
